## Local Docker results

The standard `docker buildx bake -f docker-bake.json eval-runner` target produced
`ama/pr-157-eval-runner:local` for Linux ARM64. Local image identity:
`sha256:b5df038768f2968b592fbe9708ddfaf672248d04bc2c2009d5758ac45c25e990`.
The actual image reports Python 3.14.8 and passes `pip check`, the Dockerfile's
Cosmos/repository import smoke check, CLI `--help`, and a bounded CLI dry run.

Eight existing evaluation test modules passed **101 tests** under that same
interpreter: foundations, phase-5/6 modules, rule-based/retrieval evaluators,
sanitisation, Foundry failure handling, orchestrator integration, and the
evaluation command script. Test-only pytest/asyncio tooling was installed in
an ephemeral container after the production image was observed to lack pytest;
the explicit approved feed was used, and `pip check` still passed.

An initial focused source snapshot omitted governance directories needed by
the ACR build-context contract: that run passed 100 tests and failed the one
missing-file assertion. The final snapshot includes the actual tracked
governance assets, and all 101 tests pass without changing the test or source.
Earlier package metadata failures were resolved through the approved feed;
no public-index fallback or resolver/ABI bypass was added.

The evaluation job is not a long-running Compose service. Its actual image is
tested above, while the independent unchanged application-stack check reports
eight healthy services and HTTP 200 for API, frontend, and proxied API routes.
Task services are stopped with volumes retained; an ephemeral Azurite host-port
mapping avoids an unrelated listener without changing internal endpoints.
