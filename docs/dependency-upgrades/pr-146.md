# PR #146: Node type declarations 26.6.4

## Individual plan and implementation

1. Identify the web declaration dependency and distinguish it from the actual
   Node runtime in Docker, CI, and local tooling.
2. Pin `@types/node` to 26.6.4 and regenerate its pnpm graph, including the
   matching Undici declarations, without replaying stale dependencies or
   changing the runtime, security overrides, or unrelated integrity hashes.
3. Validate a frozen install and exact installed target, then build domain
   declarations, run lint/types, production build, unit tests, and browser
   acceptance to expose declaration incompatibilities in existing code.
4. Exercise the candidate image on the real Node 24 ARM64 runtime in Compose,
   then commit and normally push to the original PR branch.

Original PR head: `b2238f8fc57f89635ca10d2790a044a2555f9ffa`.
Repaired baseline: `23f63221dd7d952ce4def98e01fd461a86c9cbbc`.
Tested source tree: `28777dc30ec1be38ae62d562e4761fb48d1e7aa5`.

No runtime upgrade or application source workaround is included. Node 26 types
can describe newer APIs than Node 24 implements; existing application code
passes the actual-runtime regression, but future code must still respect the
Node 24 runtime boundary rather than assuming every declared API is available.

postbuild. Frozen install, exact 26.6.4 assertion, domain typecheck/build,
ESLint, web TypeScript, and all 179 Vitest tests across 37 files passed.

The final route-prewarmed Chromium/mobile run passed all six cases with one
worker. An earlier concurrent run passed four and hit two cold navigation
timeouts. Existing assertions and 30-second limits are unchanged.

The independent production Compose check asserts the exact candidate web
image and records its Node 24/ARM64 runtime. Eight services are healthy and API,
frontend, and frontend-proxied API routes each return HTTP 200. Other images
remain baseline versions; only a session-local Azurite host-port override is
used. Task services are stopped without deleting volumes.
