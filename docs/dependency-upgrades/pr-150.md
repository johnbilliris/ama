# PR #150: ESLint 10.12.0 compatibility blocker

## Individual investigation plan

1. Compare the original ESLint 10 proposal with current flat configuration,
   Next lint configuration, installed plugins, Node runtime, and baseline.
2. Query the approved registry for the requested version and declared plugin
   peers. Test a package-manager-generated candidate using strict peers before
   treating it as an installable supported upgrade.
3. If a supported graph is available, regenerate the lock and run ARM64 Docker
   production build, lint/types, unit/browser regression, and stack readiness.
4. Commit and push only a supported candidate that passes those gates. Do not
   disable peer checks/rules or silently call ESLint 9 an ESLint 10 upgrade.

## Observed result

The approved proxy provides ESLint 10.12.0. The actual candidate command:

```text
pnpm install --lockfile-only --ignore-scripts
  --strict-peer-dependencies --prefer-offline
```

fails with `ERR_PNPM_PEER_DEP_ISSUES`. Current `eslint-plugin-import` 2.32.0,
`eslint-plugin-jsx-a11y` 6.10.2, and `eslint-plugin-react` 7.37.5 exclude
ESLint 10 in their supported peer ranges. The baseline Next lint configuration
is 16.2.6. Fresh package checks did not establish newer compatible versions
of those plugins. Node 24 meets the ESLint runtime requirement and is not the
blocker.

The candidate failed the supported-install gate, so no candidate Docker/browser
success, accepted upgrade commit, or push is claimed. Rules and peer enforcement
remain intact. The original remote PR head
`d1971c19598bf880cafbfd0e9a48f7dc3ca8a930` is retained unchanged.

The unvalidated candidate remains in its isolated local worktree. A future
attempt requires compatible upstream plugin/configuration releases and the
full regression gates; availability of the ESLint tarball alone is insufficient.
