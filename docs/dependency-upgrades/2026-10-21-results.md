### ESLint compatibility blocker

The approved proxy supplies ESLint 10.12.0. Availability is not the blocker.
With that exact candidate and the current workspace graph:

```text
pnpm install --lockfile-only --ignore-scripts --strict-peer-dependencies --prefer-offline
```

exits 1 with `ERR_PNPM_PEER_DEP_ISSUES`. The actual incompatible peers are
`eslint-plugin-import` 2.32.0, `eslint-plugin-jsx-a11y` 6.10.2, and
`eslint-plugin-react` 7.37.5, all of which exclude ESLint 10.
The current `eslint-config-next` is 16.2.6. Fresh checks of newer plugin releases
also did not establish ESLint 10 support. Rules and peer enforcement were not
disabled and ESLint 9 was not presented as a completed major upgrade.

### Agents Python 3.15 compatibility blocker

The baseline agents image actually contains spaCy 3.8.16, thinc 8.3.13, and
NumPy 2.4.6 under Python 3.12.14. The approved feed's published spaCy 3.8.16
metadata declares `Requires-Python: <3.15,>=3.9`; the latest other 3.8 releases
examined have the same upper bound.

The standard Python 3.15 resolver instead selected spaCy 3.8.2, thinc 8.3.2,
and NumPy 2.0.2 source distributions. The first observed native build failure
was missing `/usr/bin/g++`. A builder-only compiler retry was attempted, then
canceled after confirming the maintained-stack Python exclusion and unrelated
dependency downgrades. No terminal compiler-incompatibility error or passing
regression is invented for that canceled retry. The unvalidated candidate is
retained locally; the original remote PR head is unchanged.

### Package-feed and harness observations

Initial native-image builds received HTTP 404 for advertised `.metadata`
resources for new-interpreter shapely, pyproj, spaCy, and later source-package
artifacts. Exact artifact downloads through the approved feed succeeded, and
subsequent metadata requests succeeded. Standard Bake recipes are retried after
those checks; no public-index fallback, resolver bypass, or production-Dockerfile
resolver workaround is introduced. Ingestion and evaluation subsequently built
successfully under 3.14. The API's real pydantic-core source-build failure
required a C compiler; adding build-essential only to its builder produced a
working 3.15 image. The actual runtime was checked to contain no C compiler.
An initial metadata 404 is not proof that the wheel or interpreter is unavailable.

pnpm generation refreshed unrelated registry resolution metadata. Existing
resolution records were retained only when the package key and all other
metadata were unchanged, preserving existing integrity hashes. New package
records remain package-manager generated. Candidate validation uses frozen
installs to verify the resulting graph.

Early #143/#145 helper runs failed before meaningful tests because Windows CRLF
leaked into the Linux shell script; the session-only helper now normalizes LF.
The first #137 typecheck omitted the domain package build, so its exported
declarations were absent; the corrected harness builds the domain package first.
The initial ingestion-image pytest selection lacked `pytest-asyncio`; that
test-only plugin is restored in an ephemeral test container, not the production
image. These failed harness runs are not counted as passing application tests.
One earlier ephemeral ingestion test-plugin attempt inherited the default
public index and failed TLS; the final runs explicitly use the approved proxy,
and no public-index fallback was added to repository or production files.

Cold webpack navigation during concurrent builds caused initial two-case
Chromium timeouts for several candidates. The final complete runs prewarm the
actual API/incident/workspace routes and use one worker, retaining all
assertions and 30-second timeouts. #144 and #147 passed their original complete
browser runs. An initial application restart also hit a cold Azurite health
transition; the final helper waits for the original dependency health checks
before starting the dependent application services.

An unrelated local listener owned host port 10000. Session-only Compose
overrides remapped Azurite to 11000-11002 without changing internal endpoints,
repository configuration, or that owning process. All task application
services were stopped after validation; volumes and historical images/evidence
were retained.

Full-source archives include approximately 1 GB of tracked reference documents.
Focused web archives retain application/package/test/configuration inputs and
the needed governance assets, but omit unrelated corpus PDFs and presentations.
Their production image builds still use each independent candidate's full Git
worktree and the canonical ARM64 Bake target.
