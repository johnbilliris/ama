## Observed compatibility problem

The baseline agents image reports Python 3.12.14 and:

| Package | Actual baseline | Python 3.15 resolver fallback |
| --- | --- | --- |
| spaCy | 3.8.16 | 3.8.2 source distribution |
| thinc | 8.3.13 | 8.3.2 source distribution |
| NumPy | 2.4.6 | 2.0.2 source distribution |

The approved feed's published spaCy 3.8.16 metadata declares
`Requires-Python: <3.15,>=3.9`. Other latest 3.8 releases inspected carry the
same upper bound. Old 3.8.2 has an unbounded `>=3.7` declaration, explaining
the resolver's fallback; that omission is not current Python 3.15 support.

Early advertised-artifact metadata failures were investigated through the same
approved feed and retried. The first real source-build failure was missing
`/usr/bin/g++`, not proof of an unavailable interpreter. A builder-only
build-essential retry was started. After the current metadata and actual
baseline versions established the interpreter exclusion and dependency
downgrades, that task-owned build was canceled rather than promoting the
unvalidated older stack.

No terminal native incompatibility error is claimed for the canceled retry,
and no passing image, import, behavioral, or stack regression is claimed for
Python 3.15 agents. No `--ignore-requires-python`, build-isolation bypass,
unsupported ABI flag, public-index fallback, or production dependency downgrade
was applied.

The unvalidated compiler candidate remains in its isolated local worktree.

is unchanged. A subsequent attempt needs current-stack Python 3.15 support
