# Implementation Plan: Governance Dashboard Real Data Integration

**Branch**: `023-dashboard-real-data` | **Date**: 2025-07-18 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/023-dashboard-real-data/spec.md`

## Summary

Replace all hardcoded stub data in the governance dashboard's 6 views (health score, operational readiness, recovery progress, risk overview, compliance matrix, audit trail) with real data sourced from existing seed catalogues, domain models, and computation services. The data already exists across 6 seed files (46 data sources, 49 organisations, 27 frameworks, 123 framework assignments, 9 jurisdictions, 5 recovery domains) and domain models — the gap is wiring. A new `GovernanceDataService` will compute real metrics from seed data and stored records, feeding the existing `DashboardAggregationService` and `HealthScoreService` with real inputs. All 13 endpoints retain backward-compatible response contracts with additive metadata fields for seed fallback indication.

## Technical Context

**Language/Version**: Python 3.12+ (API), TypeScript (Web — Next.js 16.2 App Router)
**Primary Dependencies**: FastAPI, Pydantic v2, `lru_cache`-backed `SeedService`, `HealthScoreService`
**Storage**: Azure Cosmos DB (NoSQL) with in-memory fallback; JSON seed files in `packages/domain/src/domain/seed/`
**Testing**: pytest (unit, integration, contract), vitest (TS — not used for this feature)
**Target Platform**: Azure Container Apps (API), Azure App Service (Web), Australia East
**Project Type**: Web service (FastAPI API + Next.js frontend)
**Performance Goals**: <500ms p95 for all 13 dashboard endpoints
**Constraints**: No new external API calls; all data from seed files or Cosmos DB; backward-compatible API contracts; data sovereignty (Australia East)
**Scale/Scope**: 46 data sources, 49 organisations, 27 frameworks, 123 assignments, 9 jurisdictions, 5 recovery domains as baseline; must handle larger datasets
