# Contract: Truthful Inference Provenance

> Generated by SpecKit planning agent | 2026-10-18

## Identity and availability

For FR-013–FR-015, model identifier, model version and deployment alias are
independent. Use the same ResolvedDeployment used by the request, not a second
environment lookup or deployment-name parsing. Preflight-verifiable configured
identity must not be described as a response-reported model.

Existing required audit string fields retain their types and use `unknown`
when unavailable. Existing nullable wire/reply fields use null. A required
new routing field that is empty/invalid causes a pre-call error; audit
availability conventions never bypass required routing validation.

## Attempt and outcome

Add optional nullable fields to new provenance projections:

| Field | Values |
| --- | --- |
| `inference_attempted` | true, false, null |
| `inference_outcome` | `succeeded`, `failed`, `not_attempted`, `unknown`, null |
| `model_id`, `model_version` | Actual model metadata when known; unavailable conventions above |

`inference_attempted=true` requires evidence of request submission through the
SDK transport, after configuration validation, client/credential preparation,
local SDK validation and pre-call gateway checks. Entering an SDK method or a
MAF middleware alone is not submission evidence. A known local validation
exception remains false/not_attempted; unavailable submission evidence is
null/unknown, not an invented invocation. Use narrow transport/request hooks
or equivalent adapter evidence with the existing SDKs, not a framework rewrite.
Submission denotes an attempt, not proof that Azure executed a model.
Existing provider status/transport errors determine failure diagnostics.

| Case | attempted / outcome | Record semantics |
| --- | --- | --- |
| Valid completion | true / succeeded | Model, version, deployment and actual usage retained |
| Submitted request raises timeout/4xx/5xx | true / failed | Attempted destination retained; no success claim, unavailable response usage not invented |
| Partial stream then failure/cancel | true / failed | Actual partial evidence retained; not a completed response |
| Configuration/credential/client/local SDK validation failure before submission | false / not_attempted | Existing error/degraded event, no inference-call row |
| Pre-request gateway deny | false / not_attempted | Existing gateway-denial event, no claimed model invocation |
| Template/stub with no SDK call | false / not_attempted | No deployment claimed as invoked |
| Post-inference safety/template fallback | true / succeeded or failed as observed | Generation method is fallback; real attempt/usage still retained separately |
| Dispatcher HTTP response lost or local dispatch evidence unavailable | null / unknown | Attempt cannot be inferred; correlate transport/dispatcher evidence |
| Correlated submission proved, but remote completion evidence lost | true / unknown | Real attempt retained; no fabricated completion, failure or usage |
| Historical record missing new fields | null / unknown on read | Preserve bytes; no inferred status/backfill |

An empty model completion is still an attempt. A safety-filter HTTP exception
after dispatch is attempted/failed; a successful but blocked completion retains
its observed status/safety flag. Do not equate an empty summary with no call.

### Evidence boundary and per-surface admission

Submission evidence is a request-bound transport hook (or equivalent adapter
signal) that the validated model request was handed to the outbound SDK
transport for sending, with call ID and resolved destination. An SDK method,
agent/HTTP invocation, constructed request, or middleware entry alone is not
that signal. A correlated dispatcher signal can prove remote submission; an
HTTP timeout alone cannot. A locally observed submitted-request timeout is
true/failed for that request; proved submission with no observed completion
or terminal failure is true/unknown. Unknown **whether submission occurred**
is null/unknown. Neither type of unknown implies zero provider execution.

Apply this matrix consistently to new writes at every adapter/writer:

| Record surface | true (succeeded/failed/unknown completion) | false / not_attempted | null / unknown submission |
| --- | --- | --- | --- |
| Strict AuditRecord inference row / `make_inference_record` | One eligible row per proved submitted call ID, including failed or unknown completion; actual evidence only | Zero inference rows | Zero inference rows |
| Model-call usage / inference telemetry projection (common, MAF, controller, dispatcher) | One logical call projection per proved call ID; usage only when observed, never synthetic zero usage as proof | No model-call projection | No model-call projection |
| Existing agent/simulation/error/degraded event and SubAgentInvocationRecord | Retain observed attempt/outcome and agent correlation, independent of inference-row count | Retain false/not_attempted, no invoked destination claim | Retain null/unknown and uncertainty/correlation, not an invocation claim |
| Dispatcher wire / SubAgentReply | Carry observed true and outcome; known attempted destination may remain | Carry false/not_attempted; invoked identity unavailable | Carry null/unknown; invoked identity unavailable; configured target, if retained internally, is not invoked identity |

Inference admission does not create extra copies at each layer. Preserve
existing writer ownership, durability, RAG/opt-out and deduplication rules:
in an audit-enabled eligible fixture, N distinct proved submitted call IDs
produce N inference rows at the owning writer, never an aggregate or duplicate
row from an outer agent envelope. Existing opt-out suppression still applies.
For one request, writer-level expectations are 1 for true/succeeded,
true/failed and true/unknown completion, and 0 for false/not_attempted and
null/unknown submission. For a two-round controller case, first round true
and second unknown submission yields 1; both proved submitted yields 2.
Retain unknown remote outcomes in existing event/invocation envelopes even
when inference admission is zero. Correlation must not fabricate an attempt
or duplicate a dispatcher-owned inference row at the API.

## Writer and consumer changes

- Common Foundry response/usage result carries independent resolved identity
  and attempt evidence. Dispatcher uses `FoundryResponse.deployment_id`, not
  an optional `raw["deployment"]` guess. Typed identity accompanies failures
  or is available in request context before transport exception translation.
- Common mixin fallback, usage and telemetry preserve actual attempt evidence.
  Telemetry model_id is no longer the deployment name; deployment remains a
  separate attribute. Do not add prompt text or sensitive payload logging.
- Controller writes actual requests including no-RAG and failure paths; each
  tool-loop completion has a distinct call ID under the same turn correlation.
  A later tool-round failure must not erase earlier attempt records or
  attribute aggregated fallback output/usage to a successful model response.
- MAF agent audit middleware cannot infer a model request from `call_next()`:
  tools/policy failures may occur first. Supply request-boundary evidence from
  the chat adapter/middleware while preserving agent-level audit outcomes.
- API adapter removes `MODEL_DEPLOYMENT_BY_ROLE` as an identity fallback.
  Preserve the role set explicitly; role routing/AIIMS cannot depend on
  obsolete model labels. Preserve dispatcher `invocation_id` as HTTP/agent
  correlation, not automatic inference proof.
- SubAgentReply and new dispatcher responses carry nullable identity, attempt,
  outcome and optional `error`/`degraded` provenance. Existing response fields,
  six role URLs, summary/citations/prompt_hash and invocation_id remain.
  Missing new fields from an older dispatcher means unknown, never success.

## Audit compatibility and schema ordering

`packages/domain/src/ama_domain/audit_record.py` and
`packages/schemas/spec_036/audit-record-llm-call.json` currently forbid extra
fields. Add optional nullable attempt/outcome fields in both and update the
writer and affected readers/contract fixtures before enabling producers.
Do not relax additionalProperties wholesale or change required identity types.

Keep `call_kind` as inference/embedding. Known no-call and unknown-submission
outcomes use existing agent/simulation event envelopes and logging conventions,
not fabricated `make_inference_record` calls. This new-write admission policy
does not invalidate historical uncertain records or tighten historical read
validation. Preserve existing RAG/opt-out, gateway,
hash, tenant, AIIMS, replay and audit durability rules.

Extend SubAgentInvocationRecord readers and any mirrored schemas additively
for identity/attempt provenance. Its old required `model_deployment` string is
`unknown` on new unavailable records; nullable wire replies stay null.
Never rewrite historical data, run backfill migrations or retrofit status on
old records. Validate old and new fixtures concurrently, including strict
schema consumers, replay and lessons/audit exports.

## External surface constraint

No public chat endpoint or SSE event-name change is required. The internal
dispatcher contract gains optional provenance fields so old readers can ignore
them and new readers treat absence as unavailable. Deploy reader support
before writer activation. Keep current streaming order/tool semantics,
timeouts, circuit breakers, content safety and human review.
