# Implementation Plan: Performance Benchmarks

**Branch**: `feature/015-performance-benchmarks` | **Date**: 2025-07-23 | **Spec**: [spec.md](../../015-performance-benchmarks/spec.md)
**Input**: Feature specification from `/specs/015-performance-benchmarks/spec.md`
**Checklist**: [performance.md](../../015-performance-benchmarks/checklists/performance.md) (54-item deep-review)

## Summary

Expand the existing single-endpoint benchmark (`tests/benchmark/test_api_performance.py`) into a comprehensive performance benchmark suite covering all 5 agent health endpoints, pipeline processing latency, LLM client response times, and circuit breaker recovery. Store results as structured JSON in `.benchmarks/` with SLO-aligned latency targets and automated regression detection (≥ 20% warning, ≥ 50% failure). All benchmarks use pytest-benchmark, run without live Azure services, and follow a report-all (fail-at-end) strategy so every agent is always benchmarked.

## Technical Context

**Language/Version**: Python 3.12
**Primary Dependencies**: FastAPI ≥ 0.115, pytest-benchmark ≥ 5.1, pytest-asyncio, Pydantic ≥ 2.10, tenacity ≥ 9.0
**Storage**: JSON files in repo-root `.benchmarks/` directory (no database)
**Testing**: pytest with pytest-benchmark plugin (timing) and pytest-asyncio (async pipeline)
**Target Platform**: Linux (CI: ubuntu-latest via GitHub Actions), also runnable locally
**Project Type**: Test suite (part of existing multi-agent web-service project)
**Performance Goals**: Health endpoints < 100 ms (general) / < 75 ms (safety-critical: risk, evacuation); Pipeline < 2 s; LLM client mock < 500 ms; Circuit breaker recovery ≤ 2× configured timeout
**Constraints**: Full benchmark suite < 60 s wall-clock; no live Azure services; all external deps mocked in-process
**Scale/Scope**: 5 agents × 4 benchmark categories; single CI step; JSON artifact upload
